# Everyday Shop API v1

This is the local P0-07 HTTP contract. Every route returns JSON with `Cache-Control: private, no-store`, `X-API-Version: 1`, and a server-generated UUID in `X-Request-ID`. Client-supplied request IDs are ignored. Errors have `code`, `message`, `error` (legacy alias of `message`), and `requestId` matching the header. Some commerce errors also include a current `cart`, `quote`, or validation `fields`. Responses are not public cache entries.

Guest state uses the host-only, HttpOnly, Secure, SameSite=Lax `__Host-everyday-guest` cookie. A guest can read only their own cart and orders. Write requests require an `Origin` header exactly matching the request URL origin; absent, cross-origin, or `null` origins receive 403. Use browser `fetch` on the same origin with credentials. There is no login, bearer token, API-key auth, or production data reset endpoint. This demo does not accept payment credentials; `paymentMethod` selects a simulated outcome only. The cookie and same-origin check are the current CSRF defenses; they do not constitute user authentication or a general rate limiter.

## Read endpoints

| Endpoint | Success body | Notes |
| --- | --- | --- |
| `GET /api/health` | `{"status":"ok"}` | Runs D1 `SELECT 1`; any failure returns 503 `SERVICE_UNAVAILABLE` with no database details. |
| `GET /api/categories` | `{"categories":["Home","Accessories"]}` | Current catalog category names, order follows catalog data. |
| `GET /api/products` | `{"items":[Product],"total":n,"page":n,"pageSize":10,"totalPages":n,"query":CatalogQuery}` | `q` (up to 120 chars), `category=all\|Home\|Accessories`, `minPrice`, `maxPrice`, `inStock=true\|1`, `sort=featured\|price-asc\|price-desc\|name`, `page` (positive integer), `rating` (0–5), `lang=fr` or English default. Invalid supported values give 400. Page is clamped to last available page. |
| `GET /api/products/:id` | `{"product":Product,"related":[Product]}` | ID must be a positive safe integer; unknown valid ID gives 404. |
| `GET /api/cart` | `CartSnapshot` | Creates guest cookie if needed. |
| `GET /api/orders/:id` | `Order` | Only current guest's order; a missing or another guest's order gives 404. |
| `GET /api/shop` | `CartSnapshot` plus `sessionStatus` | Legacy response retained. |

`Product` retains `id`, `name`, `description`, `price` (rupees), `category`, `image`, `images`, `stock`, `rating`, and optional localization/variant fields. New additive fields are `priceMinor` (integer paise) and `currency: "INR"`. For example, a price of `1499` has `priceMinor: 149900`. Cart item fields are `{ "product": 46, "qty": 2 }`. A `CartSnapshot` includes `items`, integer `version`, `quote`, `issues`, and `checkedAt`. The quote has rupee amounts (`subtotal`, `discount`, `total`, `delivery`), paise amounts (`subtotalPaise`, `discountPaise`, `totalPaise`), `currency`, `coupon`, `valid`, and optional `couponError`. Server product, stock, coupon, and totals are authoritative.

## Writes

Send `Content-Type: application/json` and a JSON object. New cart/order REST write DTOs reject unknown top-level fields with 400 `UNKNOWN_FIELD`. Every new cart/order mutation requires `expectedVersion` (current non-negative cart version from `GET /api/cart`) and `idempotencyKey` (8–128 ASCII letters, digits, `.`, `_`, `:`, or `-`). A retry must use the same key and identical intent. Reusing a key for another intent gives 409 `IDEMPOTENCY_CONFLICT`. Cart replay returns 200 with `replayed: true` and a current cart. The version and key are in the JSON body, not request headers. `expectedPrice` is only a client expectation; it never sets a price. All quantities are absolute, never increments.

| Endpoint | Allowed JSON fields | Success |
| --- | --- | --- |
| `POST /api/cart/items` | `product` (positive integer ID), `qty` (integer 1–10), `expectedPrice?` (rupees), `expectedVersion`, `idempotencyKey` | 200 `{ "ok": true, "replayed": false, "cart": CartSnapshot }` |
| `PATCH /api/cart/items/:id` | `qty` (absolute integer 1–10), `expectedPrice?`, `expectedVersion`, `idempotencyKey` | 200 same cart mutation body; path ID must be positive. |
| `DELETE /api/cart/items/:id` | `expectedVersion`, `idempotencyKey` | 200 same cart mutation body and snapshot. The service performs the same mutation path with quantity zero. |
| `POST /api/orders` | `contractVersion: 2`, `address`, `paymentMethod`, `simulation?`, `coupon?`, `expectedVersion`, `expectedTotal?`, `idempotencyKey` | 201 new order; 200 identical replay. Both return `CheckoutResult`, including `id`, totals, the post-checkout `cart`, `status: "demo-confirmed"`, and `replayed`. |
| `POST /api/coupons/validate` | `code`, `apply?`, `expectedVersion?`, `idempotencyKey?` | 200 quote preview when `apply` is absent/false; when `apply: true`, a cart mutation result is returned. This existing endpoint preserves optional version/key compatibility; supplying both is recommended. |

For checkout v2, `address` contains exactly `name`, `email`, `phone`, `street`, `city`, `state`, and six-digit `pin`; all are required. `paymentMethod` is `card`, `paypal`, or `pay-later`. `simulation` is `success` (default), `decline`, `cancel`, or `timeout`. `expectedTotal`, when sent, is a rupee expectation. `coupon` can override the cart coupon. Checkout rejects any extra top-level or address field, including card numbers, CVV, PAN, `card`, and `paymentDetails`; do not send actual payment data. Address fields are validated by the commerce service. The service atomically records the order, redemption, and cart clearing in D1; an identical replay resolves to the original order for the same guest.

`POST /api/shop` remains the legacy compatibility adapter: `{ "action":"checkout", ... }` calls checkout, while cart actions call the same cart service. Its existing body and 200 response semantics remain; new REST DTO restrictions do not apply to it. Clients relying on `/api/shop` need no migration for this release.

## Example exchange

After `GET /api/cart` returns `version: 0`, a same-origin client can send:

```http
POST /api/cart/items
Origin: https://shop.example
Content-Type: application/json

{"product":46,"qty":2,"expectedPrice":1499,"expectedVersion":0,"idempotencyKey":"add-46-001"}
```

The 200 response is `{ "ok": true, "replayed": false, "cart": { "items": [{ "product": 46, "qty": 2 }], "version": 1, "quote": { ... }, "issues": [], "checkedAt": "..." } }`. Other quote fields follow the `CartSnapshot` definition above. A second identical request with the same key returns 200 with `replayed: true`. A stale version with a new key returns 409, for example `{ "code": "CART_CHANGED", "message": "Your cart changed in another tab. Review it before retrying.", "error": "Your cart changed in another tab. Review it before retrying.", "requestId": "<server UUID>", "cart": { ... } }`.

For `POST /api/orders`, send the latest cart version and a new key:

```json
{"contractVersion":2,"address":{"name":"Ada Example","email":"ada@example.test","phone":"9876543210","street":"1 Main Road","city":"Pune","state":"Maharashtra","pin":"411001"},"paymentMethod":"card","simulation":"success","expectedVersion":1,"expectedTotal":2998,"idempotencyKey":"order-46-001"}
```

On success the server returns 201 with `{ "id": "<order UUID>", "subtotal": 2998, "discount": 0, "total": 2998, "coupon": null, "paymentMethod": "card", "status": "demo-confirmed", "replayed": false, "cart": { ... } }`. An identical replay returns the same order ID with status 200 and `replayed: true`. `GET /api/orders/:id` returns the stored order including its `items` array.

## Status and limits

| Status | Actual examples |
| --- | --- |
| 400 | Invalid JSON/body, unknown field, malformed ID, invalid quantity, missing version/key, empty cart, invalid address or checkout contract. |
| 403 | Missing or mismatched write `Origin`. |
| 404 | Unknown product or order, including an order owned by another guest. |
| 405 | Unsupported method; JSON `METHOD_NOT_ALLOWED` and an `Allow` header. |
| 408 | Simulated payment timeout. |
| 409 | Cart/version changed, price/total/stock changed, idempotency conflict, simulated cancellation. |
| 422 | Invalid or unavailable coupon, simulated payment decline. |
| 503 | D1 health failure or commerce storage/recovery unavailable; generic error without infrastructure details. |

The API currently has no 401 path because it has no authenticated users. There is no implemented 429 rate limiter, so 429 is not promised. Orders are demo orders and do not charge a payment processor. Production writes and resets are outside this API contract.
