# P0-02 / P0-03 — catalog discovery and product detail

This slice expands the catalog to 43 deterministic demo products while retaining every original ID, name, description, price, category and primary image. It preserves Vinext, Workers, D1, the guest cookie, the absolute-quantity `/api/shop` contract and EVERYDAY rounding. No database migration or dependency addition is required.

## Behavior and architecture

- `lib/catalog.ts` parses URL criteria and applies AND filters, inclusive price/rating boundaries, stable sorting with ID tie breaks, and pages of ten. The last page contains three products; an out-of-range positive page resolves to the final page. Invalid criteria return an accessible error.
- `GET /api/products` accepts `q`, `category`, `minPrice`, `maxPrice`, `inStock`, `rating`, `sort`, `page`, and `lang`. `GET /api/products/:id` supplies a product and related products; unknown IDs return 404. Both APIs are uncached.
- Shared DTO validation rejects malformed catalog items, localized metadata and related items. Fetches cancel obsolete work, time out after12 seconds, and expose loading/error/retry states.
- Product detail supports quantity selection, stock limits, thumbnails, keyboard-operated zoom with restored focus, local fallback images, related links and new SKU variants. Variant options are distinct product IDs and therefore remain distinct cart lines without changing the database schema. The optional `wishlistSlot` is an extension point only.
- Selected quantity means amount to add. Existing qty2 plus selected qty3 becomes absolute qty5 in the legacy API. UI and server cap the final line at `min(10,stock)`. Server rejection occurs before writes. Optional `expectedPrice` rejects stale prices with409 and current metadata.
- Stock and ratings are seeded demonstration data. Inventory is not reserved or decremented. New images and secondary views are local SVG illustrations; existing primary photos remain unchanged.
